# Skill: /mach-review — Multi-Agent Voting & Escalation Panel

## Overview
`/mach-review` is the core quality assurance and governance skill of the **MACH** (Managed Agentic Construction Harness) platform. It executes a multi-agent voting protocol with complete fresh-context isolation to eliminate builder bias, enforcing non-negotiable architectural, security, and functional standards defined in `REVIEW.md`.

---

## Model Tier & Execution Parameters
- **Skill Name**: `/mach-review`
- **Assigned Models**: 
  - **High Risk**: `claude-5-5-opus` (Deep technical reasoning & threat modeling)
  - **Medium / Low Risk**: `claude-5-5-sonnet` (Balanced workhorse reviewer)
- **Context Boundary**: Must ALWAYS run in a newly spawned sub-agent context window with zero prior builder conversation history.

---

## Input Prerequisites & Evidence Check
Before evaluating code, `/mach-review` verifies that `.factory/worktrees/<ticket_id>/evidence/` contains:
1. `summary.json`: Multi-target evidence runner log generated by `/mach-verify`.
2. Target evidence files (PNG screenshots, WebM videos, VHS terminal GIFs, gRPC/REST logs, or benchmark flamegraphs).
3. Passing unit/integration test reports.
4. ProtoBuf / OpenAPI contract validation reports.

If evidence is missing or incomplete, the review panel immediately rejects the submission and returns the ticket to `/mach-build`.

---

## Execution Protocol & Multi-Agent Panel

`/mach-review` spawns **3 parallel reviewer sub-agents**, each focused on a distinct engineering discipline:

```text
                     ┌───────────────────────────────────────────┐
                     │          Candidate Git Diff               │
                     └─────────────────────┬─────────────────────┘
                                           │
         ┌─────────────────────────────────┼─────────────────────────────────┐
         ▼                                 ▼                                 ▼
[ 1. Architectural Scrutiny ]     [ 2. Security & Performance ]     [ 3. Product & UX Validator ]
(Model: Opus/Sonnet)               (Model: Opus/Sonnet)              (Model: Opus/Sonnet)
(Focus: Modularity, Proto,         (Focus: OWASP Top 10, Memory,     (Focus: Acceptance Criteria,
 Service Layer Architecture)        Input Sanitization, Latency)      Evidence Match, Intent)
         │                                 │                                 │
         └─────────────────────────────────┼─────────────────────────────────┘
                                           ▼
                               [ Multi-Agent Consensus ]
```

### Reviewer Roles & Checklists

1. **Architectural Scrutiny Agent**:
   - Inspects adherence to Service Layer Architecture.
   - Verifies zero dead code, unreferenced helper functions, or token-heavy monolithic bloat.
   - Ensures Protocol Buffer (`.proto`) and public API signatures strictly match contracts without breaking changes.

2. **Security & Performance Agent**:
   - Scans for hardcoded credentials, secret leakage, or un-sanitized inputs.
   - Evaluates memory allocations, infinite loop risks, and gRPC/REST endpoint latency.
   - Checks against `REVIEW.md` security standards.

3. **Product & UX Validator Agent**:
   - Verifies all acceptance criteria in `intent.md` and `spec.md` are satisfied.
   - Inspects `/mach-verify` evidence artifacts (PNG/WebM/GIF/Logs) to ensure visual/functional proof matches declared specs.

---

## Consensus & Voting Thresholds

Each reviewer agent outputs a vote (`APPROVE` or `REJECT`) with an itemized breakdown:

- **High Risk Tasks** (Auth, Database Migrations, Billing, Proto Contracts):
  - **Unanimous Consensus (3/3 APPROVE required)**.
  - Requires 1 Human SME approval on Gitea/Fossil/Jira/GitHub before merge.
- **Medium Risk Tasks** (Standard Business Logic, UI Components):
  - **Majority Consensus (2/3 APPROVE required)**.
- **Low Risk Tasks** (Docs, Formatting, Feature Flags):
  - **Single Reviewer Approval (1/1 APPROVE)**.

## 3-Round Iteration & Human Escalation Protocol

To prevent infinite review loops, MACH enforces a strict **3-loop maximum constraint**:

```text
                      [ Review Pass Execution ]
                                  │
                  ┌───────────────┴───────────────┐
                  ▼                               ▼
          [ All Votes Pass ]               [ Rejection ]
                  │                               │
                  ▼                               ▼
       [ Check Risk Level ]            [ Increment Review Loop ]
        - Low/Med: Auto-Merge                     │
        - High: Needs SME Sign-Off        ┌───────┴───────┐
                                          ▼               ▼
                                    [ Loop <= 3 ]   [ Loop > 3 ]
                                    Return to       Escalate to Human SME via
                                    /mach-build     /mach-ticket label:
                                                    "blocked-requires-sme"
```

1. **Rounds 1 & 2 (Automated Fix Loop)**:
   - If rejected, `/mach-review` formats an itemized, line-numbered feedback list.
   - Posts feedback to the ticket via `/mach-ticket comment <id>`.
   - Reverts ticket state to `in_progress (revision_round_N)` and triggers `/mach-build`.
2. **Round 3 Failure (Escalation Gate)**:
   - If the Builder fails to resolve defects after 3 review passes, `/mach-review` halts execution.
   - Applies label `blocked-requires-sme` via `/mach-ticket update <id>`.
   - Compiles a complete telemetry log attached to the ticket and alerts human engineering leadership.
