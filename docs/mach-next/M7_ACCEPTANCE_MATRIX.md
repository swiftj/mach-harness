### What could not be shown, and why

- **A second physical machine (rows 2, 7, 9, 15, 43, and the clean-machine half of 49).** Every product manager, engineer and Factory in M7 was a separate clone, `HOME` and Git identity on **one** Mac, sharing one GitHub account. That is a local multi-clone test, not a test on separate machines. The designated-runner question (row 15) is stated as unsupported: nothing coordinates two engineers' machines.
- **A GitHub Enterprise organisation, single sign-on, separate reviewers (rows 7, 11, 43).** Rules were tested on GitHub.com, a personal account with one user (`M7_GITHUB_RULES.md`; the repository was made public for it and rules were removed afterwards). GitHub accepted and enforced a required pull request, one approving review, code-owner review, a required check, signed commits, blocked force pushes and included administrators; a direct push, an unsigned commit and a pull request without review or check were refused; a repository ruleset's refusal was quoted to the PM. Not shown, and not possible with one account: a pull request approved under enforced review and merged (GitHub refuses a review by the author); a signed commit (the token lacks the signing-key scope; not widened); single sign-on; organisation-owned rules and merge queues. Merging needed the signature rule dropped, because one account cannot meet "signed" plus "one reviewer" with MACH's unsigned commits.
- **A clean install and an upgrade through the shipped installer, from a published release (rows 49, 51, 53).** rc.2 was published and every download, checksum and attestation verified by hand (`M7_RELEASE_CANDIDATE.md`). rc.2's own `install.sh` refused rc.2's version, so the full install path ran only through a patched scratch copy, never the shipped installer; a fresh clean machine, Linux by hand and a browser download (Gatekeeper's quarantine prompt) were not exercised. The current candidate's installer has not been verified against GitHub yet.
- **The fixes made after the third live run were not seen live.** Run 2 observed the fixes up to `62ad896`; run 3 observed `b73c025` (N1, N2, N3 observed; run 3 also found P1 to P6). Not re-observed live, each with unit tests only: N4 (acceptance published alone, `34a721e`), N5 and the scanner-report format and outcome line (`34a721e`, `1e0a635`), N6 and N7 on the Factory Floor (`1243a95`, `3a4bb22`, `ff1758a`), the review repeat and void on the page (not shown by the page at all, still open), the supervised-enable acceptance's later form, P3 belt hand-off (`9b8ad80`), P1 and P2 (`96971bd`), the blocked-request wording on GitHub (`24ed432`), the installer fixes (`072b56b`, `e3ac0e8`, `14ba169`), the observer race and Linux file identity (`acc950f`).
- **The real run integrated the product, but only on a throwaway project.** The whole five-slice wave integrated, qualified (`qualified`, deterministic) and was accepted in the second live run, then a sixth slice in the third. That is one small Python service, one Mac, one account, one operator role, and every human gate was an agent playing the engineer ("simulated"). Not shown: automatic merge (36), a verification failure and remediation (27), a reboot or network loss during an execution (14), a failure forced on purpose beyond `kill -9`, planted prompt injection against a model (57), the emergency `factory stop` path, and a dependency scan of substance (osv-scanner found no package sources; `performance` not configured).
- **Open and stated, not hidden.** Recorded cost still leaves out failed executions, killed ones have no cost at all (row 47, FAIL). Names in free text are served (row 61, FAIL, product owner's decision). No operating-system sandbox; a supervised execution runs any program as the user (`M7_THREAT_MODEL.md` T2); the acceptance of that risk is recorded, not removed. macOS programs are not notarised. The source archive is not byte-reproducible across gzip implementations. `install.sh` itself is the remaining trust root. A repeated review or voided decision is not shown on the Factory Floor page; an abandoned cell's tile still shows its last stage word. No vulnerability-reporting address exists yet.
- **Not run at all:** accessibility manual pass (65) and the Factory Floor and Studio browser suites on the final commit; a full regression at the candidate commit (62 is PARTIAL: it ran at `1d58d02`).
- **Product owner's decision, so no result yet:** names in free text (row 61), a recorded security exception for a review blocker (row 33), the cost of failed executions (row 47).

Rules for this matrix:
- **Status** is one of `PASS`, `FAIL`, `PARTIAL` (the last column says what part), `NOT RUN`, or `NOT POSSIBLE HERE` (needs a second physical machine or a GitHub Enterprise organisation with single sign-on; a tagged release is no longer a reason, rc.2 exists). A row passes only on a test or a real run that showed it. Missing evidence is `NOT RUN`, never `PASS`.
- A `PASS` that cites a test means the test existed and passed when its author or the M6.6 regression ran it. **No run of the whole suite at the candidate commit exists**; the last full run was at `1d58d02` (row 62, `PARTIAL`).
- **Kind** is exactly one of: Unit · Integration · Browser end-to-end · Controlled live Factory execution · Real multi-machine test · Mocked enterprise integration · Manual inspection. A test with a stand-in `gh` is never a real enterprise test; a run with several clones on one Mac is never a multi-machine test. Kind is unchanged from version 1. Where a row's evidence includes a live run or a simulation, the last column says so.
- **Needs** marks rows local simulation cannot complete: **2M** second physical machine; **GHEC** a real GitHub Enterprise organisation (or a real repository with branch protection); **TAG** a published, tagged release.
- **Area** cites the mandatory scenario of `DELIVERY_PLAN.md` (`DP-n`) and/or the brief's Phase 10 list (`A-n`).
- Real runs RR-M5, RR-M62, RR-M65, RR-L1, RR-L2 are defined in `M7_READINESS_INVENTORY.md`. The M7 live runs are `M7_FACTORY_ACCEPTANCE.md` (run 1, real GitHub repository, 2026-11-14, USD 8.50 recorded), `M7_FACTORY_ACCEPTANCE_2.md` (run 2, 2026-11-15, the wave finished; USD 7.93 recorded plus two killed executions with no recorded cost) and `M7_FACTORY_ACCEPTANCE_3.md` (run 3, confirmation of the N1 to N3 fixes; USD 1.93); the PM half is `M7_PM_ACCEPTANCE.md`; the enforced-rule tests are `M7_GITHUB_RULES.md`; the published candidate is `M7_RELEASE_CANDIDATE.md`. All on one Mac, one GitHub account; the engineer's gates were played by an agent ("simulated engineer").
