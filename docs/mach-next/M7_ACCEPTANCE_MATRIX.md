### What could not be shown, and why

- **A second physical machine (rows 2, 7, 9, 15, 43, 49).** Every product manager, engineer and Factory in M7 was a separate clone, `HOME` and Git identity on **one** Mac, sharing one GitHub account. That is a local multi-clone test, not a test on separate machines. The designated-runner question (row 15) is stated as unsupported: nothing coordinates two engineers' machines.
- **A real GitHub Enterprise organisation or branch protection (rows 7, 11, 43).** The test repository's plan refused classic protection, required signed commits and rulesets (HTTP 403). Required reviews, CODEOWNERS, required checks, signed commits and single sign-on were never enforced by a real service; their refusals are simulated or mocked (rows 10, 53). GitHub also refused any review by the account that opened the pull request.
- **A tagged release (rows 2, 19, 49, 52, 53, and the real-download part of 51).** The release workflow, the per-platform builds and smoke tests, attestations and the HTTPS download have never run on a tag. Only `darwin/arm64` was built, locally, and the release was stood in by a local folder.
- **The real Factory run did not finish the product.** Three of the five slices never integrated: SLICE-005 stopped on a plan defect (D5), SLICE-006 (return) and SLICE-003 (overdue report) depend on it and never started, so return and the overdue report do not exist in the integrated product. Their human gates, merges and release qualification were not exercised, and WAVE-001's product acceptance could not be recorded (D4). Rows that need those slices are PARTIAL or NOT RUN, never PASS.
- **Fixes made after the live run have unit tests and were not seen again live.** D1 to D4 (`0fcbb1b`, `1d58d02`; `M7_FACTORY_ACCEPTANCE.md`, "Corrected after the run").
- **Not run at all:** a live verification failure and remediation (row 27), automatic merge (36), reboot and network loss during an execution (14), a forced failure watched in the Tower (45), planted prompt injection against a model (57), the full regression on the candidate (62), the accessibility manual pass (65).
- **Product owner's decision, so no result yet:** names in free text (row 61, FAIL by design today), a recorded security exception (row 33), the version bump and tag (rows 49, 52).

Rules for this matrix:
- **Status** is one of `PASS`, `FAIL`, `PARTIAL` (the last column says what part), `NOT RUN`, or `NOT POSSIBLE HERE` (needs a second physical machine, a GitHub Enterprise organisation or a paid plan for branch protection, or a tagged release). A row passes only on a test or a real run that showed it. Missing evidence is `NOT RUN`, never `PASS`.
- A `PASS` that cites a test means the test existed and passed when its author or the M6.6 regression ran it. **No single run of the whole suite at one candidate commit exists yet**; that is row 62, `NOT RUN`.
- **Kind** is exactly one of: Unit · Integration · Browser end-to-end · Controlled live Factory execution · Real multi-machine test · Mocked enterprise integration · Manual inspection. A test with a stand-in `gh` is never a real enterprise test; a run with several clones on one Mac is never a multi-machine test. Kind is unchanged from version 1. Where a row's evidence includes a live run or a simulation, the last column says so.
- **Needs** marks rows local simulation cannot complete: **2M** second physical machine; **GHEC** a real GitHub Enterprise organisation (or a real repository with branch protection); **TAG** a published, tagged release.
- **Area** cites the mandatory scenario of `DELIVERY_PLAN.md` (`DP-n`) and/or the brief's Phase 10 list (`A-n`).
- Real runs RR-M5, RR-M62, RR-M65, RR-L1, RR-L2 are defined in `M7_READINESS_INVENTORY.md`. The M7 live run is `M7_FACTORY_ACCEPTANCE.md` (one supervised run, real GitHub repository, 2026-11-14, USD 8.50 recorded); the PM half is `M7_PM_ACCEPTANCE.md`. All on one Mac.
