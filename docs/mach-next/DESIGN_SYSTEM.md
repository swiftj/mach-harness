# MACH Next — Design system

The visual language and the shared frontend foundation for MACH's browser experiences: **Product Studio** (M5) and **Control Tower** (next). One family, two products. This file is the reference for anyone building screens; the code is `web/packages/ui` (`@mach/ui`) and the living specimen is `web/apps/showcase`.

```
pnpm install                 # in web/
pnpm dev:showcase            # http://127.0.0.1:4174, every token and component, both themes
pnpm dev:studio:fixtures     # Product Studio on fixture data, no host needed
pnpm lint && pnpm typecheck && pnpm build
pnpm capture                 # screenshots + axe into apps/showcase/screenshots (needs a built showcase)
pnpm contrast                # prints the contrast table below
```

## 1. Principles

1. **The engine decides; the interface shows.** No product rule lives in TypeScript. State words, refusals and suggestions come from `studio.py` and are shown as written. `@mach/ui` maps engine states to looks; it never derives a state the engine did not report.
2. **A person's acts look like acts.** Approving, sending and choosing between versions are primary buttons, always confirmed in a dialog that says what the act means. Nothing is approved because a check passed.
3. **State is never colour alone.** Every state has a word, a glyph shape and a tone. A pill reads in greyscale.
4. **Other people's words are quotations.** Reviewer remarks and text from the shared project are set as attributed quotations, never as instructions or buttons.
5. **Quiet structure, one accent.** Warm neutrals carry the page; terracotta marks the primary action and the current place, nothing else. No gradients, no decorative illustration, no emoji.
6. **Calm motion.** Motion answers an action or shows what changed. Nothing moves on its own.

## 3. Typography

| Face | Package | Role |
|------|---------|------|
| **Source Sans 3** (variable, 200–900, roman and italic) | `@fontsource-variable/source-sans-3` 5.3.1 | All interface text |
| **JetBrains Mono** (variable, 100–800) | `@fontsource-variable/jetbrains-mono` 5.3.0 | Engine identifiers (`SLICE-001`, `FR-01`), paths, digests, code |

Mono is used only where the content *is* an identifier or code; it is never a decorative label face.

| Step | Size / line | Weight | Face | Use |
|------|-------------|--------|------|-----|
| `display` | 40 / 46 | 450 | display | One per page: the project name, a page's subject |
| `title-1` | 30 / 38 | 450 | display | Page titles, section titles |
| `title-2` | 23 / 30 | 500 | display | Dialog and sheet titles, empty-state titles |
| `title-3` | 18 / 26 | 600 | sans | Panel and group headings |
| `body-lg` | 17 / 28 | 400 | sans | Product writing; the reading size keeps the extra leading |
| `body` | 16 / 24 | 400 | sans | Default interface text |
| `body-sm` | 14 / 20 | 400 | sans | Dense rows, buttons, hints |
| `label` | 14 / 20 | 600 | sans | Field labels, banner titles |
| `caption` | 13 / 18 | 400 | sans | Metadata, timestamps, legends |
| `mono` | 13 / 20 | 450 | mono | Identifiers |

Rules: sentence case everywhere; no all-caps labels; no eyebrow above a heading; reading text is kept to `68ch` (`max-w-reading`); numbers that line up use `.tabular`. Headings use `<Heading level size>` so the document outline and the visual step are chosen separately. `display` and `title-*` use `--mach-font-display`, which is Source Sans 3 in both products, set bold; there is no serif face.

## 4. Space, size and layout

- **Spacing** is Tailwind's 4px step. Inside a panel: 8, 12, 16. Between groups: 24. Between sections: 32–40. Page padding: 40px horizontal, 32px top.
- **Control heights**: 28 (`sm`, toolbars), 36 (`md`, default), 44 (`lg`, the main act of a page). Every target is at least 24×24 (WCAG 2.5.8).
- **Radius by hierarchy**: `xs` 3px (tags, IDs, keys), `sm` 5px (controls), `md` 8px (panels, banners, graph nodes), `lg` 12px (dialogs, sheets, popovers), `full` (status pills). Nothing else.
- **Density**: Product Studio is comfortable (`--mach-density: 1`). Control Tower sets 0.875, intended for its tables and logs. No component reads it yet; Control Tower's first dense components should scale row height and padding by it.
- **Shell**: rail 248px (64px collapsed), top bar 56px, content max 1200px, reading measure 68ch. Only `<main>` scrolls; the page never scrolls sideways.

## 5. Surfaces, borders, elevation

Surfaces step outward: `canvas` → `surface` (panels) → `surface-raised` (things that float). `surface-sunken` is for wells and hover. Panels have a 1px `line` border and no shadow; shadows are for floating things only:

| Level | Light | Dark | For |
|-------|-------|------|-----|
| `shadow-1` | 0 1px 2px / 6% | 0 1px 2px / 40% | Primary buttons, the project node |
| `shadow-2` | 0 2px 8px / 8% + 0 1px 2px | 0 4px 12px / 45% | Popovers, select menus |
| `shadow-3` | 0 12px 32px / 14% + 0 2px 6px | 0 16px 40px / 60% | Dialogs, sheets, toasts |

Shadows are tinted charcoal, never grey-blue. In dark, elevation shows mainly as a lighter surface.

## 6. Navigation and shell

`<AppShell nav topBar>` frames every screen of both products:

```
┌──────────┬──────────────────────────────────────────────┐
│ ■□ MACH  │ Where you are          Connected | Refreshed  │  TopBar: title, status, actions
│ Project  ├──────────────────────────────────────────────┤
│          │                                              │
│ ▌Home    │  <Page width="reading|wide|full">            │  main: the only scroller
│  Slices  │                                              │
│  Waves   │                                              │
│          │                                              │
│ ☀ ☾ ▣   │                                              │  rail footer: ThemeSwitch
└──────────┴──────────────────────────────────────────────┘
```

- **Rail** (`NavRail`, `NavSection`, `NavItem`): the current page has `aria-current="page"`, an accent bar, `accent-soft` fill and `accent-ink` label. Below 1180px the rail collapses to icons by itself; the person can toggle it. Collapsed items keep their name (tooltip and `aria-label`), and a badge becomes a dot.
- **Top bar** (`TopBar`): where you are on the left; status (connection) then at most one primary action on the right.
- **Connection** (`ConnectionIndicator`): two separate links, each with icon and words. *Host*: Connecting, Connected, Host not responding, Session ended. *Shared project*: Refreshed 14:32, Not refreshed yet, Shared project unreachable (with the engine's `problem` in the popover). Changes are announced through a polite live region. Control Tower uses the host half only.
- **Skip link**: "Skip to content" is the first tab stop.
- **Theme**: `ThemeProvider` sets `data-theme` and `data-product` on `<html>`. `ThemeSwitch` offers Light, Dark, System as a radio group; the choice is stored in `localStorage` (guarded; it falls back to the system).

## 7. Controls, dialogs, sheets, popovers

- **Button** variants: `primary` (one per region; approve, send, save), `secondary` (default), `ghost` (toolbars), `danger` (reopen, withdraw; always confirmed), `link`. `loading` keeps the width, shows a spinner and sets `aria-busy`. Labels say what happens: "Approve SLICE-001", "Send WAVE-001 to engineering", not "Submit". The toast that follows uses the same verb: "Approved SLICE-001".
- **Field** wraps label, hint, control and error and wires `id`, `aria-describedby` and `aria-invalid` into `Input`, `Textarea` and `Select`. Errors say what to do ("Use lowercase words joined by hyphens, such as team-space."). `Textarea editorial` sets product writing at the larger reading size.
- **Select** for short lists (Radix). **Checkbox** with label and description; disabled options say why they are disabled.
- **Dialog**: a decision. Title is a question, description says what the act means (both required), the confirming button is last. Focus is trapped, Escape closes, focus returns to the trigger.
- **ConfirmDialog**: the one way a personal act (`personalActs`: approve, send, reconcile) is confirmed. `onConfirm` performs the act and resolves `false` to stay open; a refusal is shown inside the dialog in the engine's own words (`error`). The confirming button shows progress and blocks a second click.
- **Sheet**: detail beside the page, from the right (400, 480 or 640px). Used for a reconcile comparison (your draft | shared project, side by side, each with its own button), a slice's check, reviewer remarks.
- **Popover**: non-modal explanation anchored to a control. **Tooltip**: names an icon-only control; never holds essential information.
- **Tabs**: underline in `accent`; arrow keys move between tabs.
- **Reading and detail** (promoted from the screens in wave 3): `RichText` renders light Markdown (paragraphs, lists, bold, code) as text, never HTML; `plain()` lowers requirement keywords (MUST, SHALL) for reading; `IdText` sets engine IDs inside a sentence as identifiers; `Disclosure` hides engineering detail (paths, Git's own words) behind a closed summary; `FactList`, `Panel`, `Stepper`. Formatting: `plural()`, `formatWhen()`.
- **Specification** (`@mach/ui`, from the spec and interview screens): `checkVerdict`, `CheckPill`, `CheckCounts` put the engine's check into words (a passing check is "ready for your approval", never "approved"); `diagnostics(check)` places each engine message next to the section it concerns; `DiagnosticList`, `OpenQuestionList`; `specModel(show)` and `whyDocument(show)` read `slice show`.

## 8. Lifecycle visualisation

Every state has a word, a glyph and a tone. The glyph vocabulary (`StateGlyph`):

| Glyph | Shape | Means |
|-------|-------|-------|
| `open` | dashed ring | nothing settled yet (draft slice, proposed epic, draft wave) |
| `half` | half-filled ring | being worked out (interviewing; changes requested; needs updating) |
| `ready` | ring with dot | settled, waiting for a person (ready for approval) |
| `approved` | solid disc with tick | a person approved it |
| `submitted` | solid disc with arrow | sent, under review |
| `accepted` | double ring | accepted into the shared project; epic completed |
| `blocked` | octagon with bar | cannot move until fixed |
| `superseded` | ring with slash | replaced or deferred; kept for history |

**Slice** (`SliceStatusPill`, `SliceLifecycle`): Draft (neutral) → Interviewing (info; shows open questions) → Ready for approval (accent) → Approved (success). Superseded (neutral, off the path). `SliceLifecycle` is an ordered list: past steps ticked, the current step marked with `aria-current="step"`, later steps quiet.

**Epic** (`EpicStatusPill`): Proposed, Approved, Deferred (warning), Completed, Superseded. **Wave** (`WaveStatusPill`): Draft, Approved, Superseded.

**Wave review** (`ReviewStatusPill`, `WaveJourney`): four stages, Approved → Sent → In review → Accepted. The engine's review word sits on its stage:

| Engine status | Stage | Tone | Glyph | Needs the PM |
|---------------|-------|------|-------|--------------|
| Not approved yet | Approved | neutral | open | |
| Approved, not sent | Approved | neutral | approved | |
| Sent, pull request not opened (shown "Sent, request not opened") | Sent | warning | blocked | yes |
| Waiting for review | In review | info | submitted | |
| Changes requested | In review | warning | half | yes |
| Blocked by a check | In review | danger | blocked | yes |
| Needs updating | In review | warning | half | yes |
| Accepted, waiting to merge | Accepted | success | approved | |
| Accepted | Accepted (final) | success | accepted | |
| Declined | In review (final) | neutral | superseded | |

The engine's `meaning` sentence is shown beside the pill when present. Reviewer remarks follow as `<Quote from kind>`.

**Where an artifact stands** (`SourceBadge`): Your draft (outline, hidden by default), Shared (outline info), Conflict (warning), Needs a new number (warning, for a collision).

## 9. Feedback states

| State | Component | When | Rules |
|-------|-----------|------|-------|
| Success | `toast({tone:"success"})` | An act completed | Past tense of the act's own name; the engine's `note` as the description. Disappears after 5s |
| Information | `Banner tone="info"`, `toast({tone:"info"})` | Refresh brought things in | A banner when it stays relevant |
| Warning | `Banner tone="warning"` | Something to settle: conflicts, collisions, approvals withdrawn, shared project unreachable | Stays until resolved; carries the action ("Settle them", "Try again") |
| Error: refused | `ErrorState` or inline | The engine said no | The engine's message shown as is; the title names what did not happen ("WAVE-001 was not sent") |
| Error: check findings | List with `blocked` glyphs | `slice check` found problems | Not an app error: the check ran. Count badge, then findings |
| Error: host | `ErrorState` + `describeError` | Network, session, protocol | Says what to do (start Product Studio again, reload) |
| Loading | `LoadingState`, `Skeleton`, `SkeletonText` | Waiting | Words say what is loading; skeletons when the shape is known; the region has `aria-busy` |
| Empty | `EmptyState` | Nothing yet | Says what belongs here, offers the one action. `headingLevel={1}` when it is the whole page |

Danger toasts never auto-dismiss. Toasts are never the only record of something the person must act on.

## 10. Motion

| Token | Duration | Easing | For |
|-------|----------|--------|-----|
| `instant` | 0 | | Checkbox ticks, selection |
| `fast` | 120ms | standard | Hover, press, focus feedback |
| `base` | 180ms | enter | Popovers, tooltips, tab changes |
| `slow` | 260ms | enter | Dialogs, sheets and toasts entering |
| `layout` | 400ms | standard | Graph re-layout, list reordering |

Easings: standard `cubic-bezier(0.2,0,0,1)`, enter `(0,0,0,1)`, exit `(0.4,0,1,1)`. Exits are faster than entrances. Only opacity and transform animate. `motion/react` users take presets from `useMachTransition(name)`.

**Reduced motion** (`prefers-reduced-motion: reduce`): every `--mach-duration-*` becomes 0; a base rule caps any remaining CSS animation or transition at 0.01ms; `useMachTransition` returns `{duration: 0}`; the graph fits without animating; skeleton shimmer and spinner rotation stop (the spinner stays visible, still). The capture script verifies that no element is still animating under reduced motion.

## 11. Graph

`@mach/ui/graph`: React Flow 12 with ELK's layered layout (loaded on first use, about 1.4MB, so screens without a graph do not pay for it).

- `productGraphFromStatus({status, reviews?, dependencies?})` builds nodes and edges from the engine's `status` (and optionally `feedback` and work-order dependencies). `layoutGraph(nodes, edges, {direction})` positions them. `<ProductGraph nodes edges onSelect selectedId ariaLabel>` renders, read-only. `<GraphOutline>` renders the same graph as a nested list; every graph view offers it.
- **Node kinds** share one component (`MachNodeView`): the kind is named in words ("Project", "Epic", "Slice") and shown by the left bar's weight (6px project, 4px epic, 2px slice); the project node is raised. Each node shows the engine ID, the title, the state (glyph and word) and either a short fact (open questions, the wave) or, in warning ink, what must be settled ("Conflict", "Needs a new number").
- **Node states** add a border style so state reads without colour: proposed (dashed), interviewing / ready / approved / submitted (solid), accepted (double), blocked (heavy, danger), superseded (dashed, faded). Mapping from the engine is presentation only (`sliceGraphState`): a slice's status, raised to submitted when its wave was sent, accepted or blocked when review said so.
- **Edges**: *contains* (project → epic → slice) thin solid `graph-edge`, recedes; *depends* dashed `graph-edge-dependency` with an arrowhead, drawn from the prerequisite to the slice that needs it, so the left-to-right order is delivery order.
- **Interaction**: no dragging or connecting (structure changes go through the engine). Tab moves between nodes, Enter or Space selects, the focus ring sits 3px outside the node. Zoom controls bottom right.
- **Control Tower** adds kinds (station, cell, agent) and states with the same vocabulary; it keeps the glyphs and border semantics.

## 12. Accessibility and keyboard

Target: WCAG 2.1 AA (and 2.2 target size).

- Contrast is enforced by the token script (section 2) in both themes.
- One focus treatment: a 2px `focus` ring, 2px offset, on every interactive element (`:focus-visible`). The resting outline colour is the focus colour too, so colour transitions never flash another colour.
- Full keyboard operation: skip link; Tab order follows reading order; Radix primitives provide arrow keys in tabs, selects and radio groups, focus trapping in dialogs and sheets, Escape to close, focus return; F8 reaches toasts; graph nodes are focusable.
- Names: icon-only buttons have `aria-label` and a tooltip; visible text is always part of the accessible name (axe `label-content-name-mismatch`).

## 13. Responsive rules

MACH targets laptops: 1280–1728px wide, and a narrower 1100px layout.

- **≥ 1180px**: rail expanded (248px).
- **1100–1179px**: rail collapses to 64px icons by itself; content keeps its 40px padding.
- **Below 1024px**: the shell keeps a 1024px minimum width rather than reflowing into a phone layout; Product Studio and Control Tower are desk tools. (Revisit if a tablet use appears.)
- Grids of specimens and panels use fractional columns with `minmax(0, 1fr)` so long IDs and paths wrap instead of overflowing; reading text never exceeds 68ch at any width.
- The capture script checks that neither the page nor `<main>` scrolls horizontally at 1440 and 1100.

## 15. API client conventions

`@mach/ui/api` holds the engine's types (derived from `web/fixtures`, one file: `api/types.ts`) and the client.

```ts
const client = createClient();                 // fetch, same origin, no-store, credentials same-origin
const status = await client.op("status", {});  // POST /api/ops/status → Status (fetches the session first)
await client.op("slice.approve", { slice_id: "SLICE-001" });
await client.writeDraft("spec", "SLICE-001", markdown, { name: "invite-teammate" });  // → { slice_id, kind, path, check }

// The interview (contract 8.2)
const current = await client.interview.current("SLICE-002");      // GET /api/interview?slice_id= → InterviewSummary | null
const { interview_id } = await client.interview.start("SLICE-002", "Admins remove people who left");
const unsubscribe = client.interview.subscribe(interview_id, {
  onEvent: (e) => { if (e.type === "question") show(e.data); },   // typed per event; e.seq is the SSE id
  onConnection: (s) => setLink(s),                                  // connecting | open | reconnecting | closed
});
await client.interview.reply(interview_id, "Yes");
await client.interview.interrupt(interview_id);   // stop this turn
await client.interview.stop(interview_id);        // end; the draft and note remain
unsubscribe();
```

- Every response must be the envelope `{ok, data}` / `{ok:false, error:{kind, message}}`. Anything else is a `protocol` error.
- Failures reject with `MachApiError { kind, message, status, operation }`. Kinds: the host's `refused | invalid | unauthorized | conflict | unavailable | internal`, plus the client's `network | protocol | aborted`. `describeError(error)` gives a title and message in the interface's voice; a `refused` message is the engine's own and is shown as is.
- GET requests carry only the session cookie. Every POST and PUT carries `Content-Type: application/json`, `X-MACH-CSRF` and same-origin credentials; when the token is not known yet, the client fetches the session first (one shared request). A 401 marks the session ended; a 403 is one refused request. Slice IDs are checked against `^[A-Z]+-\d{3,}$` before they go into a path.
- The interview stream (`client.interview.subscribe`) is an `EventSource` that the browser resumes with `Last-Event-ID`; a closed stream is reopened with back-off (2, 4, 8, 16 s, then every 15 s) and replays the current turn, so events whose sequence number (the SSE `id`) was already seen are dropped. It stops after an `ended` event.
- `client.connection` is the host connection state (`connecting | online | offline | unauthorized`); `useConnectionState(store)` feeds `ConnectionIndicator`.
- `personalActs` lists the operations that record a person's decision; screens confirm each in a dialog.
- A `Transport` can be supplied for tests and fixture mode. Product Studio uses one only under `vite --mode fixtures`; the production bundle contains no fixture code (checked by grepping the build).

## 17. Content-Security-Policy

The host serves the app under `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'`. Rules for anything added to `@mach/ui` or the apps:

- No asset is inlined as a `data:` URI except images: both apps build with `assetsInlineLimit: 0`.
- No inline `<script>` or `<style>`, no `style="..."` in served HTML. Styles set from JavaScript through the CSSOM (`element.style`, React's `style` prop, constructable stylesheets) are fine.
- Radix's scroll lock injects a `<style>` element through `react-style-singleton`. Both apps alias that package to `packages/ui/src/vendor/react-style-singleton.ts`, which adds the same CSS through `document.adoptedStyleSheets`. A new app must add the same alias.
- `web/apps/product-studio/scripts/host-check.mjs` builds the real host with the app embedded and fails on any console error, CSP violation or request leaving 127.0.0.1.
