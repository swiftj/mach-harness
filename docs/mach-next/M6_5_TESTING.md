# M6.5 Factory Analytics: browser tests, accessibility audit, performance measurement

Three tools check the Analytics workspace (`#analytics`, key `4`) in a real browser, modelled on the
Timeline's (`M6_3_TESTING.md`, `M6_3_ACCESSIBILITY.md`, `M6_3_PERFORMANCE.md`). They assert on what a
person can perceive (roles and accessible names, the figures' summaries and tables, readouts, the
address, the requests the page makes) and never compare pixels.

| Tool | File | Modes |
|---|---|---|
| Browser tests | `web/apps/control-tower/e2e/analytics-proof.e2e.mjs`, `analytics-shell.e2e.mjs`, `analytics-live.e2e.mjs` | proof, live |
| Accessibility audit | `web/apps/control-tower/scripts/analytics-audit.mjs` | proof, shell, live |
| Performance | `web/apps/control-tower/scripts/analytics-measure.mjs` | proof, live |
| Shared plumbing | `web/apps/control-tower/e2e/analytics-lib.mjs`, `e2e/analytics-global.mjs` | |

## Modes

- **proof**: the areas' development proof page (`/src/analytics/dev/proof.html`, never built) on the
  seeded simulated fixture, and the Shell's `#analytics` over the built-in Simulation (`?simulation`).
  Needs only the Vite dev server. Everything shown there is labelled Simulated, and the tests check it.
- **live**: `mach-observer` built from the working tree with plain `go build` into the scratch folder
  (never `apps/observer/build.sh`, which swaps a shared folder), run on a project generated by
  `mach-synth --analytics` into the scratch folder, and the Shell's `#analytics` reading it through the dev
  server's `/api` proxy and a relay (the Timeline suite's arrangement). Nothing is copied from elsewhere:
  the projects are generated with the commands in the table below.

| Project | Command (`mach-synth --out <dir> --analytics ...`) |
|---|---|
| empty | none: a folder with `.factory/config.json` = `{}` |
| one run | `--cells 1 --waves 1 --seed 3` |
| tiny | `--cells 2 --waves 1 --seed 1` |
| medium | `--cells 60 --waves 8 --seed 1` |
| large | `--cells 330 --waves 40 --events 240000 --seed 1` (240,000 events, three weeks) |

## Running them

```
cd web/apps/control-tower
pnpm run test:e2e:analytics                                   # all three files, one at a time
E2E_AN_MODE=proof pnpm run test:e2e:analytics                 # proof only (no Go needed)
E2E_AN_MODE=live  pnpm run test:e2e:analytics                 # live only
node --test --test-global-setup=e2e/analytics-global.mjs e2e/analytics-shell.e2e.mjs   # one file

node scripts/analytics-audit.mjs --mode proof                 # or --mode shell, --mode live [--project tiny|medium|<dir>]
node scripts/analytics-measure.mjs --mode proof
node scripts/analytics-measure.mjs --mode live [--project large] [--reuse] [--runs 5] [--append-rate 200 --append-seconds 15]
node scripts/analytics-measure.mjs --mode live --project large --compare-baseline <mach-observer binary>
```

`--compare-baseline` runs the same observer measurements (rebuild, restart, every query, idle, append) a
second time with another binary, on an identical copy of the project taken before anything is appended,
and prints both columns plus a per-query table. To build the M6.3 baseline without touching any checkout:

```
mkdir -p /tmp/b37 && git archive b37c036 apps/observer | tar -x -C /tmp/b37
cd /tmp/b37/apps/observer && go build -o /tmp/mach-observer-b37c036 ./cmd/mach-observer
```

The baseline has no `flow`, `contributors` or `insights` route and refuses two `group_by` dimensions;
those rows say "not served". It also accepted unknown parameters silently, so its "windowed",
"distribution", `at` and comparison timings are for the unwindowed head query, not like for like. Run the
comparison on a quiet machine: the observer figures are what it is meant to settle.

Ports 4430-4439 only: the dev server 4430 (with `MACH_OBSERVER_PORT=4439`), the relay 4439, observers
4432, 4433, 4436, 4437 (browser tests), 4434 (audit), 4435 (measurement). Every process started is
recorded in `<scratch>/pids` and killed by the global teardown, or by the file or script that started it.
Each file reuses a dev server already answering on 4430; a dev server started without
`MACH_OBSERVER_PORT` serves proof mode but not live mode.

| Variable | Default | What |
|---|---|---|
| `E2E_AN_MODE` | `all` | `proof`, `live` or `all` |
| `E2E_AN_SCRATCH` | `<os tmpdir>/mach-analytics-e2e` | binaries, generated projects, observer logs |
| `E2E_AN_DEV_PORT`, `E2E_AN_RELAY_PORT` | 4430, 4439 | |
| `E2E_HEADED` | unset | `1` shows the browser |

The audit writes to `--out` (default `<os tmpdir>/mach-analytics-audit`), the measurement to `--out`
(default `<os tmpdir>/mach-analytics-measure`): a JSON report, and for the audit the accessibility tree of
Pulse and a screenshot per area. Neither writes into the repository.

## Hooks the tools read

Agreed with the areas and shell agents; where one is missing the dependent test skips and names it.

| Hook | Where | Used for |
|---|---|---|
| `[data-analytics-workspace]` with `data-analytics-source=simulation\|live\|replay` | Shell | which source the workspace shows |
| `data-analytics-area`, `-ready`, `-window="<from>-<to>"`, `-cursor` | workspace root | readiness, the effective window, the cursor every query of the view used |
| `figure[data-chart]` with `aria-labelledby`, `aria-describedby` and a Table/Chart toggle | each chart | name, summary, data-table alternative |
| `[data-readout=<metric id>]` with `data-value` only when there is a number | each readout | comparing what is shown with the API |
| `[data-state=not-recorded\|unavailable\|deferred]` | unavailable figures | a reason, never a number |
| `[data-analytics-brush]` with two `role=slider` handles | brush | brushed range |
| `button[data-analytics-chip]` | filter chips | applied filters, clearing them |
| `aside[data-analytics-rows]` with `a[data-ref]` | Rows drawer | drill-down to entities |

Without the `-ready` hook, readiness is the sheet on screen plus a short settle.

## What each covers

### `analytics-proof.e2e.mjs` (proof page, simulated fixture)

| Test | Proves |
|---|---|
| areas | every area renders on its sheet, the workspace bar says Simulated, each figure has a name, a summary and a table |
| window preset | 7 days changes the stated window, every figure table's days fall inside it |
| brush | a drag across Pulse's first brushed chart changes the stated window and shows the chosen-window indicator (`[data-analytics-chip-window]`); its Undo restores the period |
| filters | Risk = high changes Quality's figures and the address; Clear removes it |
| cross-filter | a station pressed on the Flow map is pressed, in the address, and shown as a chip (`[data-analytics-chip]`) that names it and clears it |
| Rows | in each area that offers Rows: focus moves into the drawer, rows are entity refs in the ref grammar linking to `#timeline?sel=<ref>`, Escape closes it |
| deep links | `area`, `window`, `risk`, `app_type` load into the controls, are written back, and the written address reopens the same view |
| unavailable | in the default, two-run (`mode=sparse`), no-lifecycle (`mode=nolog`) and `model=opus` states, every unavailable readout or block gives a reason and no number |
| sideways | nothing scrolls sideways at 1512x982, 1280x800, 1100x700 in any area |
| requests | every request is a GET to 127.0.0.1, no prose (whitespace, sentence-like or over 128 characters) in any address, no console error |

### `analytics-shell.e2e.mjs` (Shell, built-in Simulation)

| Test | Proves |
|---|---|
| keys | `1` floor, `2` Blueprint, `3` Timeline, `4` back to Analytics with its area, window and filter; the workspace switch shows Analytics |
| deep links | `#analytics?area&win&risk&app&model` for every area loads into the controls and round-trips |
| invalid values | an unknown area, window, risk or a script in `station` is ignored without an error |
| Rows → Timeline → floor → Back | a row opens the Timeline with `sel=<ref>`, selected; `1` keeps it on the floor; Back returns to Analytics with its area and filter |
| Back from a key switch | Back after `3` returns to Analytics with its area, window and filter |
| sideways, requests | as above, with the inspector open |

### `analytics-live.e2e.mjs` (real observer on empty, one-run, tiny and medium)

| Test | Proves |
|---|---|
| routes | `metrics`, `flow`, `contributors`, `runs`, `insights` answer on each project with `cursor`, `generated_ms`, `filters`, `history` (a route not served yet skips) |
| missing is not zero | on the empty project no rate has a value and every metric without one says why |
| cursor | the same `at` gives the same figures; an unknown parameter is a 400 |
| areas | every area over each project, the source said (Live, Historical replay), never Simulated, unavailable figures give a reason |
| numbers are the observer's | each `[data-readout]` with `data-value` equals the value the page's own metrics request returns; where the API has none the page shows none |
| window preset | after 7 days, every analytics request of the area carries one `at` and one window, equal to `data-analytics-cursor`; the address says `win=7d` |
| brush | the brushed window is read at one cursor and written to the address |
| filters | Risk = high reaches every request; a chip clears it |
| Rows | the row's entity opens in the Timeline selected, its interval (from `contributors`) inside `data-timeline-window`; `1` keeps it on the floor; Back restores Analytics |
| deep links, keys | as in the Shell file, over the live source |
| through the playhead | with the playhead held mid-history, every metrics request carries `to_ms`, and each readout equals the API at that `to_ms` (not the head) |
| sideways, requests | as above |

Every browser test in this file skips, with the reason, while the Shell mounts its placeholder for a live
source.

### `analytics-audit.mjs`

1. axe (WCAG 2.2 A/AA tags) on every area, both themes, the default, two-run, no-lifecycle and model
   states (proof), every figure as a table, the Rows drawer open.
2. Keyboard: Tab order filters > areas > sheet, a visible focus at every stop (outline, shadow, the mark's
   ring, or pixels that change), Tab comes back round; at most one Tab stop in each chart's plot, and an
   arrow key moves focus inside it; the Rows drawer takes focus, keeps it over 40 Tabs and 5 Shift+Tabs,
   and gives it back to the Rows button on Escape.
3. Target sizes: 24 px or spaced (WCAG 2.5.8); inline links in sentences are exempt.
4. Contrast of named chart marks (3:1) and SVG chart text (4.5:1; 3:1 when large) against their composited
   ground, both themes.
5. Colour independence: inside each chart, marks of different colours must also differ in shape, dash,
   pattern, status or the words of their names.
6. Reduced motion: nothing runs after an area switch, a window change, a hover and opening the drawer.
7. Every drawn chart has a name, a summary and a table.

### `analytics-measure.mjs`

Proof and live: the workspace's first figure from navigation; area switch, window preset, filter and
Compare from the action to the last DOM change it caused (quiet for 150 ms); hover to the tip; brush
(when there is one); JS heap after GC before and after. Live only: the observer's cold rebuild (no index)
and restart (saved projection) on the project; every `/analytics/*` query cold and warm (`--runs`),
windowed, grouped, with distribution, with `last_runs`, with `at`; a comparison (two filtered queries at
one cursor, together); the observer's CPU and RSS idle for 10 s and while `mach-synth --append` adds
events, CPU per appended event, and the time to catch up after the last append.

(`<scratch>/run.lock`) and a second run refuses with the holder's pid.

## Known gaps

- **Through the playhead** is reached with `#analytics?area=pulse&at=<ms>` (the middle of the medium
  history); the test requires every query made while it is held to carry `as_of_ms` (or `to_ms`) no later
  than the playhead and each readout to be among the API's numbers at that bound.
- **Readouts vs the API**: a readout's `data-value` must be one of the numbers the observer returned for
  that metric (value, numerator, denominator, a percentile, a sum); it cannot tell which one the label
  claims. Reloads are compared at 9 significant digits.
- **Several windows in one area** (a trend asking for earlier periods) are logged, not failed; one cursor
  per view is required.
- **Pick values with a space** (`target_kind:matrix rule`) would be flagged by the prose-in-URL check; the
  tests do not use one.
- **Unavailable-not-zero in the UI** is checked by readout text in proof mode and, in live mode, by
  comparing each `[data-readout][data-value]` with the value of the page's own metrics request; figures
  drawn only in SVG (no readout) are covered by the API test and the chart's table, not compared number
  by number.
- **Colour independence** is a heuristic: marks are grouped by colour within one chart and must differ in
  shape, dash, pattern, status or the words of their names. A legend beside the chart is not counted.
- **Contrast** reads computed SVG paint against the composited background; a plate behind text is counted
  as a mark and may be a false positive.
- **Pixels** are never compared; geometry is the unit tests' (`test/*.test.mjs`).
- `test:e2e:timeline` now lists the Timeline's five files instead of `e2e/*.e2e.mjs`, so it no longer runs
  these.
- **Observer cost** (idle CPU 26 %, 6 ms CPU per appended event, 71 s rebuild, 22 s restart) is over the
  proposed budgets on a loaded machine. They are not called regressions until re-measured on a quiet
  machine with `--compare-baseline` against a b37c036 build.
